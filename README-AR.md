# VibeChat — خطوات التشغيل من الهاتف

## 1) ارفع الملفات
ارفع `index.html` و`style.css` و`app.js` و`firestore.rules` إلى جذر مستودع GitHub الذي تملكه. يمكن فتح الملفات وإضافة محتواها عبر زر Add file في GitHub.

## 2) فعّل تسجيل الدخول
في Firebase Console:
- Authentication → Get started
- Sign-in method → Email/Password → Enable → Save

## 3) تأكد من Firestore
في Firestore Database أنشئ قاعدة البيانات إذا لم تكن موجودة. اختر منطقة مناسبة لك. لا تستخدم قواعد الاختبار المفتوحة.

## 4) أنشئ حساب المالك أولًا
افتح الموقع من رابط الاستضافة، وأنشئ حسابك ببريدك. بعد التسجيل:
- Firebase Console → Authentication → Users
- افتح حسابك وانسخ UID.
- في `app.js` استبدل `REPLACE_WITH_OWNER_AUTH_UID` في سطر `ADMIN_UID` بـ UID الخاص بك.
- في `firestore.rules` استبدل النص نفسه بـ UID الخاص بك.
- انشر قواعد `firestore.rules` من Firestore → Rules → الصق القواعد → Publish.

**مهم:** لا تجعل UID أو البريد وحده وسيلة حماية. القواعد المنشورة هي التي تفرض صلاحيات الوصول. لا تضع مفاتيح سرية في GitHub.

## 5) النشر
Firebase Hosting لا ينشر من مستودع GitHub تلقائيًا دون إعداد تكامل/Workflow. أسهل طريق من الهاتف:
- افتح Firebase Console → Hosting → Get started.
- إذا طلب CLI أو أوامر محلية، استخدم إعداد GitHub deployment من إعدادات Hosting/GitHub إن كان متاحًا في مشروعك، أو استخدم GitHub Actions مع إعداد نشر Firebase Hosting.
- بعد نجاح النشر سيظهر رابط ينتهي عادة بـ `web.app`.

## ما الذي تتضمنه هذه النسخة؟
- تسجيل حساب وتسجيل دخول بالبريد وكلمة المرور.
- دردشة عامة فورية تحفظ الرسائل في Firestore.
- صفحة مالك تعرض المستخدمين (حتى 200 حساب في النسخة الأولية).
- قواعد أساسية تحمي الرسائل وبيانات المستخدمين.

## ما الذي لم يُفعّل بعد؟
- لا توجد مدفوعات حقيقية ولا تحويل تلقائي إلى Binance في هذه النسخة.
- لا توجد إدارة لتعطيل حسابات Firebase Auth؛ ذلك يتطلب Cloud Functions أو خادمًا موثوقًا يستخدم Firebase Admin SDK.
- لا تُفعّل الاشتراكات بناءً على إدخال المستخدم. يلزم مزود دفع/تكامل تجاري مناسب، والتحقق من Webhook على الخادم قبل منح الباقة.
- لا يوجد تشفير طرفي للرسائل؛ لا تستخدمها لمعلومات حساسة.

## ملاحظة أمنية
إعداد Firebase للويب الظاهر في `app.js` هو إعداد عميل وليس كلمة مرور إدارية. حافظ على قواعد Firestore المقيدة، وفعّل App Check عند الاستعداد للإطلاق العام.
